# AWS EKS Infrastructure for MLOps (Lesson 5-6)

Цей проєкт містить Terraform-конфігурацію для автоматизованого розгортання інфраструктури в AWS (region: eu-central-1), розробленої для задач MLOps. Конфігурація оптимізована для мінімізації витрат.

## Архітектура інфраструктури

Проєкт розгортає наступні компоненти:

- **VPC**: Побудована за допомогою офіційного модуля `terraform-aws-modules/vpc/aws`. Включає:
  - Публічні та приватні підмережі.
  - NAT Gateway для забезпечення виходу приватних нод в інтернет.
- **EKS Кластер**: Версія 1.34.
- **Managed Node Groups**:
  - `cpu-node-group`: Базові вузли для системних компонентів кластера.
  - `ml-node-group`: Спеціалізовані вузли для розгортання та тестування ML-моделей.
  - *Типи інстансів підібрані згідно з лімітами Free Tier та навчальних бюджетів.*



## Як користуватися проєктом

### 1. Попередня підготовка

Переконайтеся, що у вас встановлені та налаштовані:
- **Terraform** (v1.5.0+)
- **AWS CLI** (авторизований через `aws configure`)
- **kubectl**

### 2. Розгортання (Step-by-Step)

Через особливості створення залежностей для EKS, розгортання виконується у два етапи:

1. **Ініціалізація проєкту:**

terraform init

2. **Першочергове створення мережі (VPC):**
Це необхідно для коректного визначення підмереж перед створенням кластера.

terraform apply -target=module.vpc

3. **Розгортання решти інфраструктури (EKS та Node Groups):**

terraform apply


### 3. Підключення до кластера

Після завершення `apply`, оновіть ваш локальний конфіг `kubectl`:

aws eks update-kubeconfig --region eu-central-1 --name mlops-eks-cluster

**Перевірте статус нод:**

kubectl get nodes

## Тестування

Для перевірки працездатності інфраструктури можна запустити тестовий под:

kubectl run ml-test --image=python:3.9-slim -- sleep 3600
kubectl get pods

## Видалення ресурсів

Щоб уникнути зайвих витрат в AWS, видаляйте інфраструктуру після завершення роботи:

terraform destroy
